# 哈希表

哈希表通过哈希函数把键映射到固定数量的桶中，再用冲突处理策略保存落在同一个桶里的键。本例使用**除留余数法** `h(key) = ((key % 7) + 7) % 7` 计算桶号，使用**链地址法**处理冲突：每个桶挂一条链，冲突键按插入顺序追加到链尾。查找、插入、删除都先定位桶，再沿链逐个比较，平均复杂度为 `O(1 + α)`，最坏所有键同桶时退化为 `O(n)`。

## 输入格式

输入是一组依次插入的键，逗号或空白分隔。界面先按顺序建表，再在表上执行查找、插入或删除。

默认输入：

```text
50, 23, 15, 36, 44, 8, 60
```

对应的桶：

```text
0: ∅
1: 50 → 15 → 36 → 8
2: 23 → 44
3: ∅
4: 60
5: ∅
6: ∅
```

计算过程：

```text
50 mod 7 = 1      23 mod 7 = 2      15 mod 7 = 1
36 mod 7 = 1      44 mod 7 = 2       8 mod 7 = 1
60 mod 7 = 4
```

规则：

- 至少要有 1 个键，最多 15 个键。
- 每个键都是 -999 到 999 的整数。
- 负键也参与取模，桶号为 `((key % 7) + 7) % 7`，一定能落在 `0..6`。
- 初始键序列内不允许重复键；需要演示重复插入时，使用「插入」操作并输入已存在的目标键。
- 目标键同样必须是 -999 到 999 的整数。

常见错误：

| 情况 | 提示 |
| --- | --- |
| 空输入 | 请输入键序列，例如 `50, 23, 15, 36, 44, 8, 60`。 |
| 非整数或越界 | 请输入最多 15 个整数，范围 -999 到 999。 |
| 重复键 | 键序列包含重复键 X，哈希表不接受重复键。 |
| 目标键非法 | 目标键须为 -999 到 999 的整数。 |
| 插入超过上限 | 最多展示 15 个键，无法继续插入。 |

查找未命中、删除未命中、插入已存在的键都不是输入错误，动画会在最后一帧说明结果。

## 画面语义

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| 未访问 | 灰色 | 还没有进入当前桶的比较链 |
| 当前桶 / 当前键 | 琥珀色 | 本帧哈希定位到的桶，或正在比较/修改的键 |
| 已比较 | 蓝色 | 当前桶链上已经比较过的键 |
| 空桶 | 虚线 | 桶头为 `null`，本帧可能报告未找到 |
| 链边 | 灰色箭头 | 同一个桶内从前往后的链接 |

画布顶部固定显示一条公式：

```text
除留余数法  h(key) = ((key % 7) + 7) % 7
```

当帧里有当前键和桶号时，公式条改为显示代入结果，例如：

```text
h(8) = ((8 % 7) + 7) % 7 = 1
```

这样即使当前帧只点亮桶、没有点亮链节点，也能直接看到桶号是如何算出来的。

## 帧模型

- **创建**：对每个键先发哈希帧，再发该桶链上的比较帧，最后发插入帧。空桶只有哈希帧和插入帧；默认序列共 21 帧。
- **查找**：准备帧 + 哈希帧 + 链上比较帧 + 命中/未命中帧。
- **插入**：准备帧 + 哈希帧 + 链上比较帧 + 插入/已存在帧。
- **删除**：准备帧 + 哈希帧 + 链上查找帧 + 删除帧；未命中时以“删除取消”结束。
- 最后一帧的旁白说明“完成”或结果，不再单独增加完成帧。
- 每帧包含键节点、同桶链边、7 个桶头、当前桶、当前键、已比较键、旁白和代码锚点；调用栈与队列为空。
- 切换操作或应用新输入后回到第 0 帧。

操作下拉顺序是创建、查找、插入、删除；默认选中查找，进入页面时先看到完整表与准备帧。

## 四种操作

### 创建

按输入顺序逐个插入。每个键先计算桶号，再沿该桶已有的链比较；如果键不存在，就在链尾创建节点。

```text
build(keys):
    table = array of 7 empty chains
    for key in keys:
        bucket = hash(key)
        node = table[bucket]
        while node != null:
            if node.key == key:
                break
            node = node.next
        if node == null:
            append new Node(key) to table[bucket]
    return table
```

- 哈希帧锚点 `hash`，旁白：`插入 X：h(X) = X mod 7 = B，定位到 B 号桶。`
- 比较帧锚点 `compare`，旁白：`比较 X 与 Y：不相等，沿链继续。`
- 插入帧锚点 `insert`，旁白：`在 B 号桶链尾插入 X。`
- 最后一个插入帧追加：`建表完成，共 n 个键。`
- 链地址法采用尾插法，已有键的位置不会因为新键插入链头而整体移动。

### 查找

先计算桶号；桶为空直接未找到；否则从链头开始逐个比较，相等就命中，走到链尾仍未相等就未找到。

```text
search(table, target):
    bucket = hash(target)
    node = table[bucket]
    while node != null:
        if target == node.key:
            return node
        node = node.next
    return null
```

- 准备帧锚点 `start`，旁白：`准备查找 X：先计算桶号。`
- 哈希帧锚点 `hash`，高亮目标桶。
- 比较帧锚点 `compare`；命中帧锚点 `found`，旁白：`在 B 号桶找到 X。`
- 空桶未命中帧锚点 `miss`，旁白：`B 号桶为空，未找到 X。`
- 链尾未命中帧锚点 `miss`，旁白：`比较 X 与 Y：不相等，链结束，未找到 X。`
- 默认查找 8：`start`、`hash`、`compare(50)`、`compare(15)`、`compare(36)`、`found(8)`。

### 插入

插入先按查找的走法定位桶并遍历链。若键已存在则不重复插入；否则在链尾创建节点。

- 准备帧锚点 `start`，旁白：`准备插入 X：先计算桶号。`
- 哈希帧与链上比较帧同查找。
- 已存在帧锚点 `exists`，旁白：`比较 X 与 Y：相等，键已存在，不重复插入。`
- 插入帧锚点 `insert`，旁白：`在 B 号桶链尾插入 X。插入完成，共 n 个键。`
- 默认插入 29：`start`、`hash`、`compare(50)`、`compare(15)`、`compare(36)`、`compare(8)`、`insert(29)`。
- 表已有 15 个键时，新键无法插入；已存在的键仍然可以显示 `exists`。

### 删除

删除严格先定位桶并查找，再修改链。未找到时不做任何结构修改。

```text
delete(table, target):
    bucket = hash(target)
    node = table[bucket]
    prev = null
    while node != null:
        if target == node.key:
            break
        prev = node
        node = node.next
    if node == null:
        return table
    if prev == null:
        table[bucket] = node.next
    else:
        prev.next = node.next
    return table
```

三种情形：

1. **链头**：桶头改为目标的后继。锚点 `remove`，旁白：`删除 B 号桶的链头 X，链头改为 Y。删除完成。`
2. **链中/链尾**：前驱的 `next` 改为目标的后继。锚点 `remove`，旁白：`在 B 号桶中删除 X，前驱 P 指向后继 S。`（尾节点写“指向空”。）
3. **唯一节点**：桶头置空。锚点 `remove`，旁白：`删除 B 号桶中唯一的键 X，桶变空。删除完成。`

- 删除帧不显示目标徽章；当前桶保持高亮。
- 默认删除 15：`start`、`hash`、`compare(50)`、`found(15)`、`remove`。
- 删除 50：`start`、`hash`、`found(50)`、`remove`。
- 删除 8：`start`、`hash`、`compare(50)`、`compare(15)`、`compare(36)`、`found(8)`、`remove`。
- 未命中时最后锚点 `miss`，旁白：`未找到 X，删除取消。`

## 代码锚点

代码面板提供 C / C++ / Python / Go / Java / Rust 六个版本，所有语言共用同一组行尾锚点。节点结构假定已定义，包含 `key` 与 `next`。

| 操作 | 帧使用的锚点 | 模板中包含的锚点 |
| --- | --- | --- |
| 创建 | `hash`、`compare`、`insert` | `start`、`hash`、`compare`、`insert`、`done` |
| 查找 | `start`、`hash`、`compare`、`found`、`miss` | 上述全部 + `done` |
| 插入 | `start`、`hash`、`compare`、`insert`、`exists` | 上述全部 + `done` |
| 删除 | `start`、`hash`、`compare`、`found`、`miss`、`remove` | 上述全部 + `done` |

未知操作回退到查找模板。哈希行统一写成 `((key % 7) + 7) % 7`，避免负键在 C / C++ / Java / Go 中产生负桶号。

## 布局与边界

- 顶部公式条高 20，固定显示除留余数法；有当前键时显示代入结果。
- 7 个桶按行排列，每行左侧是桶格，右侧是冲突链；行高 24，桶格与键节点高 20。
- 键节点为 36×20 的圆角矩形，链上相邻节点间距 20。
- 舞台高度固定为 208；公式条与 7 行桶都在这段高度内。
- 画布宽度由整段 trace 的最长链决定，步进时不会改变；最长链超过默认宽度时横向滚动。
- 节点 id 在整段 trace 内稳定；插入和删除导致链位置变化时，已有节点平滑移动。
- 删除链头后，新链头向左移动；链中删除后，后继节点依次前移。
- 空表仍然显示 7 个空桶与公式条，不显示“空树”文案。

## 边界与测试

- 空桶未命中、非空桶链尾未命中、命中链头/链中/链尾。
- 删除链头、链中、链尾、唯一节点，以及删除未命中。
- 重复插入已存在的键，验证 `exists` 且结构不变。
- 负键 `-1`、`-7`、`-8` 的桶号分别为 `6`、`0`、`6`。
- 15 个同桶键：验证节点不重叠、不越界，画布横向滚动；再插入新键时报错。
- 重复输入、空输入、目标键越界、插入超过 15 个键。
- 每个操作每一帧的锚点都必须在六种语言模板中存在；代码显示文本不能残留 `@anchor`。
- 场景几何测试覆盖创建、查找、插入、三种删除、空桶未命中与负键；公式条始终在画布内且不压住第一行桶。
- 每帧所有键都必须恰好出现在某条桶链中；`bucketHeads` 与 `links` 不能引用已删除节点。

## 实现约定

- 键节点 id 按插入顺序从 0 开始分配；删除不回收 id，插入继续递增，保证跨帧身份稳定。
- `items` 按 id 升序排列，因此 **`active` / `settled` 是 items 下标**；`bucketHeads` 与 `links` 使用节点 id。
- `bucketHeads` 长度固定为 7，`null` 表示空桶；`activeBuckets` 是桶号数组，当前帧通常只有一项。
- `links` 只包含同桶链边 `[fromId, toId]`，按桶号 0..6、再按链上顺序生成。
- 哈希函数统一使用 `hashSlot`，即 `((key % 7) + 7) % 7`；不要直接写 `key % 7`。
- 链地址法采用尾插法；删除时同步更新桶头或前驱的 `next`，然后从存活链重新生成 `items`、`links` 和 `bucketHeads`。
- 操作 `create`、`search`、`insert`、`delete` 与代码模板键一致。
- 工作台按整段 trace 的最长链传入 `hashChainCapacity`，保持画布宽度稳定；桶数固定为 7。
